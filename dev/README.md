# dev/ — scene lab

Dev-time only. Nothing here ships: `index.html` never loads these files, and
`test/static-guards.test.js` pins that page's script list, so adding to `dev/`
cannot leak into the site.

`scenelab.html` renders the scene engine in isolation, straight from
`file://` — no server, no build. It loads the real `js/data/frames.js`,
`js/data/sprites.js` and `js/scene.js`, so what you see is what the site
composes.

## Query params

| param | effect |
|---|---|
| `?frame=duck` | one meerkat pose in the full scene (default `sentry`) |
| `?sprite=tree1` | a single sprite alone — `sun`, `moon`, `tree1`, `tree2`, or any pose name |
| `?anim=idle\|dance` + `?step=N` | exactly the Nth step of an animation, no timers — deterministic, so screenshots are stable |
| `?anim=dance&play=1` | run the scheduler live, as `ui.js` does |
| `?time=22:00` | override the clock that drives the sky |
| `?fs=36` | render at a large font, for judging sprite detail |
| `?grid=1` | row/column ruler overlay, for placing sprites |
| `?bare=1` | drop the info line |

## Verification recipes

Screenshots go to a scratch directory, never into the repo.

```bash
LAB="file:///home/johan/data/meerchat/dev/scenelab.html"
SHOT="google-chrome --headless=new --disable-gpu --window-size=1100,900 --screenshot"

# one sprite, big, to judge whether it reads
$SHOT=/tmp/shot/tree1.png "$LAB?sprite=tree1&fs=20"

# the floor-stays-put check: the dune line must sit at the same height in both
$SHOT=/tmp/shot/sentry.png "$LAB?frame=sentry&time=12:00"
$SHOT=/tmp/shot/duck.png   "$LAB?frame=duck&time=12:00"

# time-of-day sweep
for t in 06:30 12:00 18:30 22:00; do
  $SHOT=/tmp/shot/sky_${t/:/}.png "$LAB?frame=sentry&time=$t"
done

# screencast of an animation: deterministic frame series -> contact sheet + gif
for i in $(seq 0 11); do
  $SHOT=/tmp/shot/dance_$(printf %02d $i).png "$LAB?anim=dance&step=$i&time=12:00"
done
ffmpeg -y -i /tmp/shot/dance_%02d.png -vf "scale=300:-1,tile=4x3" /tmp/shot/contact.png
ffmpeg -y -framerate 4 -i /tmp/shot/dance_%02d.png -vf "scale=420:-1" /tmp/shot/dance.gif
```

The whole page, at both sizes and with motion suppressed:

```bash
PAGE="file:///home/johan/data/meerchat/index.html"
google-chrome --headless=new --disable-gpu --window-size=980,760 \
  --virtual-time-budget=3000 --screenshot=/tmp/shot/desktop.png "$PAGE"
google-chrome --headless=new --disable-gpu --window-size=390,844 \
  --virtual-time-budget=3000 --screenshot=/tmp/shot/mobile.png  "$PAGE"
google-chrome --headless=new --disable-gpu --window-size=980,760 --virtual-time-budget=3000 \
  --force-prefers-reduced-motion --screenshot=/tmp/shot/still.png "$PAGE"
```

Interaction is not screenshot-testable (headless Chrome cannot type), so the
chat → route → scene chain is covered by `test/ui-wiring.test.js`, which runs
the real `js/ui.js` against a DOM stub and a controllable clock.

## Drawing sprites

Charset: the meerkat frames use `# ' * + - . : = @ ^` (they were generated by
an image-to-ASCII pass at 141x73). Scenery may also use `/ \ |` for branches,
and deliberately avoids `#`: the dense fills read as "near", so keeping them
for the meerkat is what makes the trees sit back as background.

Iterate in a scratch script that prints candidate art to the terminal — the
silhouette is much faster to judge as text than as a screenshot — then paste
the result into `js/data/sprites.js` and check it at scene scale in the lab.
Rows are easiest to keep aligned by writing them unpadded and symmetric about
their own centre, then centring them on a shared axis programmatically.

Two traps worth knowing, both learned the hard way:

- A wide crown over a hairline stem reads as a **wine glass**, not a tree.
  Visible limbs converging on the trunk are what make it read as a tree.
- Never splice or edit rows 71–72 of a meerkat pose. They carry the baked-in
  dune line and feet marks; `scene.js` strips the dots there so the scene's
  ground layer is the only floor.
